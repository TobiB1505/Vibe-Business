# V1 — what "finished" means

**Status: draft. Nothing here is decided until the founder strikes and adds.**

This file exists because the project had no end. [docs/ROADMAP.md](ROADMAP.md) is a register of known gaps, and it is good at that — but a list of imperfections has no last entry. Every audit adds to it, every sprint finds more, and it grows faster than it closes. As long as it was the only map of "what is left", there was structurally no way to be done.

So: this is the other list. It is short, it is closed, and everything not on it is explicitly not V1.

## What V1 means

> **A stranger can sign up, pay, and get value from Vibe without the founder standing next to them.**

One sentence, and it is testable. Every item below exists because that sentence is not true yet. Nothing else belongs here — not because it does not matter, but because a list that admits everything that matters is the list this file replaces.

## What V0.1 was, and why it is over

[PRODUCT.md §7](../PRODUCT.md#7-v01-scope) lists seventeen things V0.1 had to do and says, in its own words, **"All of the above are implemented."** That is true and it has been true for weeks. V0.1's job was to prove the Core Loop runs end to end. It does.

V0.1 proved the loop **works**. V1 asks whether a stranger can **use** it. Those are different questions, and the second one has never been asked as a whole.

## The list

Five items. If this list grows past a handful, something has gone wrong with the definition above rather than with the product.

### 1. A customer cannot watch what they are paying for

An agent run costs 150–350 Credits and takes minutes. `coding-agent/observability/live-view.ts` builds a complete live model — status, activity, files — and every lookup in `coding-agent/store.ts` is keyed by an operation id or a run identity, so no surface can ask "what is this project doing right now". A founder presses Run and the screen tells them nothing until it is over.

*Named in [ROADMAP.md](ROADMAP.md), "No surface can show an agent run in flight". Sharper since [ADR 0092](decisions/0092-the-agent-runs-as-the-product.md): the agent is the product now, not an internal experiment.*

### 2. The loop cannot confirm the agent's own work

Outcome verification is the product's third promise — *did the change actually do anything?* — and it cannot see agentic changes. So for exactly the work Vibe now sells, the loop ends at "merged" and says nothing after.

*Named in [ROADMAP.md](ROADMAP.md), "Outcome verification cannot see agentic changes".*

### 3. Deleting a real project has never been done

One deletion has run through the deployed UI, on a project holding a repository connection and nothing else. The cascade for a project with an audit, a plan, a spec, an approval and a merge is proven in isolation by migration tests and has never fired end to end. Neither has Disconnect, Reconnect, or any live refusal.

A paying customer deleting their account is not a place to find out.

*Named in [ROADMAP.md](ROADMAP.md), "Project deletion is dogfooded for the empty case only"; the bar is [ADR 0056](decisions/0056-lifecycle-erasure-and-retention.md) §17.*

### 4. A wrongly-classified change gets no visual review, and nothing notices

`review/classification.ts` decides whether a change needs a human to look at a picture of it. It is load-bearing since [ADR 0063](decisions/0063-review-classification-as-a-gate.md), its fallback is the permissive direction, and nothing measures how often the fallback decides.

*Named in [ROADMAP.md](ROADMAP.md), "A wrongly-classified change gets no visual review, and nothing would notice".*

### 5. Nobody has walked the whole loop as a stranger

Sign up, buy Credits, connect a repository that is not Vibe's own, run the audit, take the plan, run the agent, review, approve, merge, and see the outcome — once, in order, with real money, on somebody else's product.

Every part of that is tested. Several parts are dogfooded. **The whole has never been walked**, and rule 69's fourth question is exactly about the difference. The agent in particular opened to customers on 2026-09-07 and has never run for one.

*Not a ROADMAP entry, because it is not a gap in a component. It is the definition of V1 with the word "test" in front of it.*

## Explicitly not V1

Everything else in [ROADMAP.md](ROADMAP.md). It stays there, it stays true, and it stops competing for attention until the five above are done. That includes work that is genuinely good and genuinely worth doing:

- The 26% usage-projection gap — real, and inert: nothing reads that table.
- Cache-token metering, unverified sandbox rates, the thin calibration dataset — margin accuracy, not customer value.
- The evidence pack not being persisted; contradictions computed and never sent to the model; evidence ids minted twice — reasoning quality.
- Per-lens score history, snapshot history, "nothing learns from a run" — features V1 does not promise.
- An admin surface for corrections — `pnpm billing:refund` already moves the money; a screen is product work with its own decision.
- The project workspace showing the typed project label instead of the product's own name — cosmetic.

None of that is cancelled. It is **after**.

## How this list may change

An item leaves by being done. An item joins **only when a person decides it does** — never because an audit found something, never because a session thought it was important, never because it is adjacent to something on the list.

That rule is the whole value of the file. A list that anything may join is the ROADMAP, and the ROADMAP already exists.
