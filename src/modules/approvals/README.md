# modules/approvals

Approval Layer — see [ARCHITECTURE.md §3.10](../../../ARCHITECTURE.md#310-approval-layer). Enforces that merges to the default branch only ever follow an explicit, attributable user action, per [PRODUCT.md §9](../../../PRODUCT.md#9-approval-model).

Built. An approval is a row binding one person's decision to one immutable artifact identity — project, prepared change, commit, base, validation run, **the evidence a person was shown**, and policy version, hashed, with a partial unique index on it ([ADR 0018](../../../docs/decisions/0018-human-approval-authority.md)). `identity.ts` is what makes "approved" mean *approved this exact commit*: change any part of the artifact and the old consent no longer covers it.

The evidence takes one of three forms, and which one a change is entitled to is decided by `modules/review`'s classification, never by what happens to exist ([ADR 0063](../../../docs/decisions/0063-review-classification-as-a-gate.md), [ADR 0065](../../../docs/decisions/0065-the-preview-is-the-review.md)).

A change that alters no rendered page names a `code_review_digest`: a hash of the two commits, the shown paths and the diff policy version, so what a person looked at can be regenerated byte for byte. A change that alters one names that digest **and** the `preview_sessions` row of the same commit — the sandbox is gone within fifteen minutes, but the row is immutable and says that an interactive preview of exactly these bytes ran and became reachable at `ready_at`. The third form, a `review_artifacts` row of two stored screenshots, exists only on rows created before Sprint 0114; nothing produces one now.

The diff is in every new form, because a preview shows what a change looks like and only the diff shows what it does. Three database CHECKs admit exactly those three shapes and no fourth, and the insert policy verifies whichever form a row carries.

The merge gate deliberately does not re-ask the classification. It reads the evidence form off the approval row, because the classification depends partly on the analyzer's route table and that table moves — a standing human decision must not become unfindable because of a table nobody saw when they made it (rule 68).

An approval authorizes nothing on its own. Whether a merge may happen is a second question, asked against live repository state immediately before the write by `modules/merge` ([ADR 0019](../../../docs/decisions/0019-safe-approved-change-merge.md), rules 68, 70).
